# 二期路线图：从一次性实验到可重复基准

## 起点

一期已完成一次完整的对比实验，脚本链本身已具备可复现能力：

```
tools/build.py → tools/verify.py → tools/probe.js → tools/shot.mjs
```

`build.py` 生成自包含页面，`verify.py` 调用无头 Chrome，`probe.js` 在页内计算像素指标，`shot.mjs` 用 CDP 真实等待探针完成后导出截图。目前所有产物都在仓库中，可直接查看。

## 二期目标

把「针对一张图、手工跑一次」改成「针对固定输入集、一条命令跑完并输出结构化结果」。这样每次改动都能得到可比较的数字，也便于在 CI 中自动回归。

## 进度

- [x] 一期全部产物与像素级验证（见 [experiment-report.md](experiment-report.md)）
- [x] 把 `verify/metrics.txt` 中的指标结构化为 `results/metrics.csv`，可直接被脚本或表格工具读取
- [x] 整理仓库结构、补在线演示说明与复现文档
- [ ] 固定输入集：准备多张轮廓复杂度不同的图像，统一命名与尺寸基线
- [ ] 自动采集：一条命令遍历输入集，导出统一格式的 CSV 与截图
- [ ] 分组实验：分辨率 × 轮廓复杂度，输出分组对比表
- [ ] CI：GitHub Actions 在无头 Chrome 上自动跑基准并归档结果

## 验收标准

1. 在干净环境执行一条命令，能产出 `results/` 下完整的指标表与截图，无需手工干预
2. 同一输入重复跑两次，关键指标波动在可解释范围内
3. 新增输入或修改渲染参数后，能直接看出指标变化，不需要重新写分析脚本
4. 结论能落到「什么场景适合矢量 / 双 GPU 管线 / 生成式栅格」的量化判断上

## 为什么分阶段做

先把结果结构化、把复现路径写清楚，再扩展输入集和自动化。这样每一步都有可演示、可核对的产出，而不是等全部做完才拿出来。
